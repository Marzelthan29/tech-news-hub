## 🚀 Cómo Contribuir

1. **Haz Fork del Repositorio**
   ```bash
   git clone https://github.com/yourusername/tech-news-hub.git
   cd tech-news-hub
   ```

2. **Crea una Nueva Rama**
   ```bash
   git checkout -b add-new-source
   ```

3. **Haz tus Cambios**
   - Agrega fuentes a los archivos de categoría apropiados
   - Sigue las pautas de formato a continuación
   - Prueba todos los enlaces para asegurarte de que funcionen

4. **Haz Commit de tus Cambios**
   ```bash
   git add .
   git commit -m "Agrega [Nombre de la Fuente] en [Categoría]"
   ```

5. **Push y Crea PR**
   ```bash
   git push origin add-new-source
   ```
   Luego crea un Pull Request en GitHub

## ✅ Pautas de Contribución

### Estándares de Calidad

**✅ INCLUIR:**
- Fuentes de alta calidad y confiables
- Blogs/sitios activos (actualizados en los últimos 6 meses)
- Contenido gratuito o freemium
- Fuentes en inglés (principalmente)
- Descripciones claras y precisas
- Enlaces funcionando

**❌ NO INCLUIR:**
- Contenido promocional o spam
- Contenido de pago (a menos que esté claramente indicado)
- Blogs inactivos (6+ meses sin actualizaciones)
- Blogs personales sin contenido sustancial
- Fuentes duplicadas ya listadas
- Enlaces de afiliados (a menos que estén divulgados)

## 📝 Agregando una Nueva Fuente

### Plantilla de Formato

Al agregar una fuente, usa este formato markdown:

**Para tablas:**
```markdown
| [Nombre de la Fuente](https://example.com/) | Breve descripción del contenido | Frecuencia de Actualización |
```

**Para listas:**
```markdown
- [Nombre de la Fuente](https://example.com/) - Descripción de lo que la hace valiosa
```

## 🗂️ Sugiriendo una Nueva Categoría

Si crees que nos falta una categoría importante:

1. **Abre un Issue** con:
   - Nombre de la categoría
   - Breve descripción
   - Por qué es necesaria
   - Al menos 10-15 fuentes de calidad para la categoría

## 🔗 Reportando Enlaces Rotos

¿Encontraste un enlace roto? ¡Ayúdanos a corregirlo!

1. **Abre un Issue** titulado: "Enlace Roto: [Nombre de la Fuente]"
2. **Incluye:**
   - Enlace que está roto
   - Categoría/archivo donde está ubicado
   - Reemplazo sugerido (si está disponible)

**O** ¡envía un PR con la corrección directamente!

## 🎯 Mejores Prácticas

### Al Agregar Fuentes

1. **Verifica el Enlace** - Asegúrate de que funcione
2. **Busca Duplicados** - Busca en el archivo primero
3. **Usa Formato Adecuado** - Sigue los estándares markdown
4. **Escribe Descripciones Claras** - Ayuda a los usuarios a entender el valor
5. **Coloca en la Categoría Correcta** - Usa la sección más apropiada
6. **Mantén Orden Alfabético** - Dentro de las subsecciones cuando sea posible

### Pautas de Descripción

**Buena Descripción:**
```markdown
- [Blog de Martin Fowler](https://martinfowler.com/) - Artículos en profundidad sobre diseño de software, patrones de arquitectura y refactorización
```

**Mala Descripción:**
```markdown
- [Blog de Martin Fowler](https://martinfowler.com/) - Blog sobre programación
```

## 📜 Código de Conducta

### Nuestro Compromiso

Estamos comprometidos a proporcionar una experiencia acogedora e inclusiva para todos.

### Comportamiento Esperado

- Sé respetuoso y constructivo
- Acepta críticas constructivas con gracia
- Enfócate en lo que es mejor para la comunidad
- Muestra empatía hacia los demás

### Comportamiento Inaceptable

- Acoso o lenguaje discriminatorio
- Trolling o comentarios insultantes
- Spam o abuso promocional
- Publicación de información privada de otros
