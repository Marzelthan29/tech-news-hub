## 📝 Translation Guidelines

### What to Translate

**Priority 1 - Core Files:**
- ✅ README.md
- ✅ CONTRIBUTING.md
- ✅ QUICKSTART.md

**Priority 2 - Categories:**
- Category introduction files
- Maintain original source links (most are in English)
- Translate descriptions and navigation

**Priority 3 - Additional:**
- Format files (newsletters, podcasts, etc.)
- Issue/PR templates

### What NOT to Translate

- ❌ Source names (keep original)
- ❌ URLs and links
- ❌ Code examples
- ❌ Technical terms (unless commonly translated)
- ❌ Brand names

### Translation Best Practices

1. **Keep the same structure** - Follow the English version's organization
2. **Use natural language** - Don't translate literally; adapt to local culture
3. **Maintain formatting** - Keep all markdown formatting intact
4. **Update internal links** - Ensure links point to the correct language version
5. **Keep badges** - GitHub badges work in all languages

## 🤝 Contributing Translations

### Adding a New Language

1. **Create directory structure:**
   ```bash
   mkdir -p lang-code/categories
   mkdir -p lang-code/formats
   ```

2. **Translate core files:**
   - README.md
   - CONTRIBUTING.md
   - QUICKSTART.md

3. **Add language navigation:**
   - Update all README files with new language link
   - Format: `[🇫🇷 Français](fr/README.md)`

4. **Submit PR** with translation

### Improving Existing Translations

1. Fork the repository
2. Edit the appropriate language file
3. Ensure accuracy and natural flow
4. Submit PR with clear description
